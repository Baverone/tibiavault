# Bosses e Bosstiary — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a página «Bosses» do TibiaVault. Tem as rotações diárias solo e team por áreas, o Bosstiary de cada personagem gravado no GitHub e o boss boosted do dia.

**Architecture:**
- O catálogo fixo (`src/data/bosses/catalogo.json`) é gerado por um script a partir das pesquisas guardadas em `data/bosses-fontes/`.
- O domínio puro, em `src/domain/bosses/`, faz as regras do Bosstiary, o estado e a rotação. É testado com `node --test`.
- O estado de cada personagem vive em `data/bosstiary/<id>.json` e grava-se pela API de conteúdos do GitHub. Usa o mesmo código dos skills, que fica extraído para `githubContents.ts`.
- A página é React e segue a casca e as `PAGES` que já existem.

**Tech Stack:** React 19, TypeScript 6, Vite 8, `node --experimental-strip-types --test` (o `npm test`), oxlint.

**Spec:** `docs/superpowers/specs/2026-11-22-bosses-design.md`

## Global Constraints

- **Textos visíveis:** em português de Portugal, como no resto do site.
- **Imports locais:** com a extensão `.ts` explícita nos módulos alcançados pelos testes (`node --test`), como em `constants/players.ts`.
- **Ficheiros de estado:** `data/bosstiary/royal-paladin.json` e `data/bosstiary/exalted-monk.json`. A chave do GitHub é a que já existe (`storage/githubToken.ts`, `tibiavault:github-token`). Nunca é escrita por código nosso fora desse módulo.
- **Regras do Bosstiary:**

  | Categoria | Kills (P/E/M) | Pontos (P/E/M) |
  |---|---|---|
  | Bane | 25/100/300 | 5/15/30 |
  | Archfoe | 5/20/60 | 10/30/60 |
  | Nemesis | 1/3/5 | 10/30/60 |

  O 2.º slot abre aos 1 500 pontos.
- **Boss boosted:** uma kill nele soma 3. A fonte é `https://api.tibiadata.com/v4/boostablebosses`.
- **Objetivo por omissão** dos bosses «bosstiary»: Mastery para Archfoe e Nemesis, Prowess para Bane.
- **Cooldown desconhecido** (`null` no catálogo): conta como 20 h.
- **Nível do Monk em falta:** usa o do RP + 150 e fica marcado como estimativa.
- **Gravação:** em fila, num commit só, 2 s depois do último clique. As alterações são diferenças aplicadas sobre o que se lê, nunca o ficheiro inteiro escrito por cima.
- **O `localStorage` dos skills** e o prefixo `'calculadora-hunt:'` não se tocam.

## Review Focus

1. **Dois aparelhos a gravar ao mesmo tempo**, por exemplo um +1 no telemóvel e outro no PC. As duas kills têm de ficar (409/422 → reler e reaplicar). Coberto na Task 4.
2. **Fechar a página com gravações na fila.** Aviso `beforeunload` enquanto há alterações por gravar. Uma falha fica à vista com «tentar outra vez» e nunca se perde em silêncio. Coberto na Task 6.
3. **Sem chave do GitHub ou sem rede.** A página lê, mostra o estado e diz «falta a chave para gravar», sem rebentar. Coberto na Task 6.
4. **TibiaData em baixo, ou o boosted com um nome que não está no catálogo.** A rotação aparece na mesma. O nome aparece no topo, com a nota «não está no catálogo». Coberto na Task 5.
5. **Kills escritas à mão com lixo** (negativo, texto, decimal). O valor é limpo para um inteiro ≥ 0. Coberto na Task 3.

### Task 3: As regras do Bosstiary e o estado de cada personagem

**Files:**
- Create: `src/domain/bosses/bosstiary.ts`, `src/domain/bosses/estado.ts`
- Test: `src/domain/bosses/bosstiary.test.ts`, `src/domain/bosses/estado.test.ts`

**Interfaces:**
- **`bosstiary.ts`:**
  - `LIMIARES: Record<Categoria, [number, number, number]>`
  - `patamar(kills: number, cat: Categoria): Patamar`
  - `pontos(kills: number, cat: Categoria): number`. Os valores acumulados são 0/5/20/50 para Bane e 0/10/40/100 para os outros.
  - `proximo(kills: number, cat: Categoria): { patamar: Patamar; faltam: number } | null`
  - `objetivoOmissao(cat: Categoria): Patamar`
  - `chegouAoObjetivo(kills: number, cat: Categoria, objetivo: Patamar): boolean`
  - `bonusLoot(pontosTotais: number): number`. É uma percentagem com as regras da spec: 25 % aos 0 pontos, +1 % por cada 10 pontos até 50 % aos 250, +1 % por cada 20 até 100 % aos 1 250. Depois disso, o 1 % número x custa 20 + 5x pontos.
- **`estado.ts`:**
  - `interface EstadoBoss { kills: number; ultimaKill: string | null; acesso: boolean | null; marcaSolo?: Marca; marcaTeam?: Marca; objetivo?: Patamar; passou?: boolean }`
  - `interface EstadoPersonagem { bosses: Record<string, EstadoBoss>; pontosJogo: number | null }`. A chave de `bosses` é o `id` do boss.
  - `type Alteracao = { tipo: 'kill'; id: string; quantas: number; quando: string } | { tipo: 'kills'; id: string; valor: number } | { tipo: 'marca'; id: string; modo: Modo; marca: Marca } | { tipo: 'acesso'; id: string; acesso: boolean | null } | { tipo: 'objetivo'; id: string; objetivo: Patamar } | { tipo: 'passou'; id: string; passou: boolean } | { tipo: 'pontosJogo'; valor: number | null }`
  - `limparEstado(raw: unknown): EstadoPersonagem`. Aceita `null` ou lixo e devolve um estado vazio. As kills ficam como inteiro ≥ 0.
  - `aplicar(estado: EstadoPersonagem, alteracoes: Alteracao[]): EstadoPersonagem`. É pura e não muta o original.
  - `estadoDe(estado: EstadoPersonagem, id: string): EstadoBoss`. Devolve o boss ou um valor por omissão: `kills 0`, `acesso null`.
  - `acessoEfetivo(eb: EstadoBoss): boolean | null`. Fica `true` se houver kills maiores que 0 e `acesso` for diferente de `false`; senão devolve `acesso`.

### Task 5: A rotação do dia e o boosted

**Files:**
- Create: `src/domain/bosses/rotacao.ts`, `src/storage/boostedBoss.ts`
- Test: `src/domain/bosses/rotacao.test.ts`, `src/storage/boostedBoss.test.ts`

**Interfaces:**
- **`rotacao.ts`:**
  - `interface Entrada { boss: Boss; estado: EstadoBoss; marca: Marca; disponivelEm: number | null; boosted: boolean; nivelEstimado: boolean }`. `disponivelEm` fica `null` quando o boss já está disponível; senão é o timestamp em que volta.
  - `interface BlocoHoje { bloco: Bloco; entradas: Entrada[]; minutos: number }`
  - `interface Contexto { agora: number; diaSemana: number; nivel: number | null; personagem: 'royal-paladin' | 'exalted-monk'; boosted: string | null }`
  - `rotacaoSolo(cat: Catalogo, est: EstadoPersonagem, ctx: Contexto): { blocos: BlocoHoje[]; endgame: Entrada[] }`
  - `rotacaoTeam(cat: Catalogo, est: EstadoPersonagem, ctx: Contexto): { principais: BlocoHoje[]; soBosstiary: BlocoHoje[] }`
  - `marcaEfetiva(boss: Boss, eb: EstadoBoss, modo: Modo): Marca`. Por omissão: `valor` `equipamento` ou `lucro` dá `sempre`, `bosstiary` dá `bosstiary`.
- **`boostedBoss.ts`:** `lerBoosted(fetchFn?): Promise<string | null>`. Lê `boostable_bosses.boosted.name`. Em erro, ou se a forma for inesperada, devolve `null`. A forma do JSON confirma-se com um `curl` antes de escrever o teste.

**Regras da rotação**, as da spec (secção «Regras de omissão»):
- **Fica de fora** um boss com marca `fora`, com `acessoEfetivo === false`, ou com `bosstiary` e o objetivo atingido.
- **Nível:** o filtro é `nivelRp` para o RP e `nivelMonk ?? nivelRp + 150` para o Monk. Um `null` passa.
- **Blocos `semana`:** entram só os que têm `diaSemana === ctx.diaSemana`. O `f44` entra sempre.
- **`endgame`:** só entra nos `blocos` com `passou`; senão fica em `endgame`.
- **`disponivelEm`:** é `ultimaKill + (cooldownH ?? 20) h`, quando isso ainda está no futuro.
- **Boosted:** a comparação do nome não liga a maiúsculas e minúsculas.
- **`minutos` do bloco:** é a soma dos `minutos` das entradas disponíveis.
- **Team:** um bloco é `principal` se tem pelo menos uma entrada com `valor` diferente de `bosstiary`. Os finais com cooldown acima de 24 h só aparecem quando `disponivelEm === null`. Os outros aparecem também em cooldown, a cinzento.

  - Um boss com `nivelRp 500` e `nivelMonk` a `null` aparece para o Monk 700, com `nivelEstimado: true`.
